Step 1: Install Redux and React-Redux

To start using Redux, you need to install two libraries: redux (the core library) and react-redux (which connects Redux to your React components). These must be installed in your project, in this case, react-number-adder. The installation process is the same for both Mac and Windows, but you’ll need to ensure Node.js and npm are installed on your system.

Prerequisite: Install Node.js (which includes npm) from nodejs.org. Choose the LTS version for stability. After installation, verify by running node --version and npm --version in your terminal (Command Prompt or PowerShell on Windows, Terminal on Mac).

For Mac and Windows:

  • Open a terminal (on Mac: Terminal; on Windows: Command Prompt, PowerShell, or Git Bash).
  • Navigate to your project directory and install the required packages:
# Navigate to the project directory and install Redux and React-Redux
cd react-number-adder
npm install redux react-redux

Notes:

  • The cd command works the same on both Mac and Windows. For example, if your project is in C:\Users\YourName\react-number-adder on Windows, use cd C:\Users\YourName\react-number-adder.
  • The npm install command adds redux and react-redux to your project’s node_modules and updates package.json.
  • If you’re using npx for other tasks (e.g., creating a React app with npx create-react-app react-number-adder), note that npx is included with Node.js and works on both platforms, but it’s not needed for this installation step.

Step 2: Create and Configure Redux Store

Create a central store to hold the application's state. Make a new file called store.js in the src/ directory:

import { createStore } from 'redux';

// Initial state - holds the application's data, including a count and a history of actions
const initialState = {
  history: [],
  count: 0
};

// Reducer function to handle actions and update the state
const reducer = (state = initialState, action) => {
  switch (action.type) {
    // Actions to modify the state
    case 'UPDATE_HISTORY':
      console.log('UPDATE_HISTORY', state, action.payload);
      return {
        ...state,
        history: [
          ...state.history.slice(0, action.payload),
          ...state.history.slice(action.payload + 1)
        ]
      };

    case 'RESET':
      console.log('RESET', state);
      return {
        ...state,
        history: [...state.history, 'RESET'],
        count: 0
      };

    case 'ADD_1':
      console.log('ADD_1', state);
      return {
        ...state,
        history: [...state.history, 1],
        count: state.count + 1
      };

    case 'ADD_2':
      console.log('ADD_2', state);
      return {
        ...state,
        history: [...state.history, 2],
        count: state.count + 2
      };

    case 'REMOVE_1':
      console.log('REMOVE_1', state);
      return {
        ...state,
        history: [...state.history, -1],
        count: state.count - 1
      };

    case 'REMOVE_2':
      console.log('REMOVE_2', state);
      return {
        ...state,
        history: [...state.history, -2],
        count: state.count - 2
      };

    default:
      return state;
  }
};

const store = createStore(reducer);

export default store;

Wrap the entire application with the Provider component in index.js to make the store available to all components:

import React from 'react';
import ReactDOM from 'react-dom/client';
import './index.css';
import App from './App';
import store from './store';
import { Provider } from 'react-redux';
import reportWebVitals from './reportWebVitals';

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    <Provider store={store}>
      <App />
    </Provider>
  </React.StrictMode>
);

Step 3: How Redux Works at a High Level

Redux is a predictable state container for JavaScript apps. At a high level:

  • Store: A single source of truth that holds the state (e.g., count and history) of your application.
  • Actions: Descriptions of events (e.g., ADD_1, UPDATE_HISTORY) that change the state.
  • Reducers: Pure functions that take the current state and an action, and return a new state.
  • Dispatch: The mechanism to trigger actions to update the state.

Step 4: Reading and Writing Redux Content in a Component

Use the useSelector and useDispatch hooks to read data from the Redux store or dispatch actions. Below are two example components: ResultBar, which displays the count and history, and ControlCenter, which provides buttons to modify the state.

Example 1: ResultBar Component

This component displays the current count and a list of history items. Clicking a history item removes it from the list by dispatching the UPDATE_HISTORY action with the item's index.

import './ResultBar.css';
import React from 'react';
import { useSelector, useDispatch } from 'react-redux';

function ResultBar() {
  // Read count and history from the Redux store
  const count = useSelector((state) => state.count);
  const history = useSelector((state) => state.history);
  
  // Get the dispatch function to trigger actions
  const dispatch = useDispatch();

  return (
    <div className="resultbar">
      <h3>Result</h3>
      <p id="resultId">{count}</p>
      <p id="totalMessage"></p>
      <h3>History List</h3>
      <div id="summary"></div>
      <ul id="historylist">
        {history.map((item, i) => (
          <li
            key={i}
            onClick={() => dispatch({ type: 'UPDATE_HISTORY', payload: i })}
          >{item}</li>
        ))}
      </ul>
    </div>
  );
}

export default ResultBar;

In this component:

  • useSelector reads count and history from the store.
  • useDispatch provides the dispatch function to trigger actions.
  • The history array is rendered as a list, and clicking a list item dispatches the UPDATE_HISTORY action with the item's index as the payload, removing that item from the history.

Example 2: ControlCenter Component

This component provides buttons to modify the count and history by dispatching actions like ADD_1, REMOVE_2, and RESET. It uses named handler functions for dispatching, which is a more structured approach for handling multiple actions.

import './ControlCenter.css';
import React from 'react';
import { useDispatch } from 'react-redux';

function ControlCenter() {
  // Get the dispatch function to trigger actions
  const dispatch = useDispatch();

  // Handler functions for each action
  const handleRemove2 = () => {
    dispatch({
      type: 'REMOVE_2'
    });
  };

  const handleRemove1 = () => {
    dispatch({
      type: 'REMOVE_1'
    });
  };

  const handleReset = () => {
    dispatch({
      type: 'RESET'
    });
  };

  const handleAdd1 = (notification) => {
    dispatch({
      type: 'ADD_1',
      payload: notification
    });
  };

  const handleAdd2 = () => {
    dispatch({
      type: 'ADD_2'
    });
  };

  return (
    <div className="controlcenter">
      <h3>Control Center</h3>
      <div className="controlbuttons">
        <button id="minustwo" onClick={() => {
          console.log("-2");
          handleRemove2();
        }}>-2</button>
        <button id="minusone" onClick={() => {
          console.log("-1");
          handleRemove1();
        }}>-1</button>
        <button id="reset" onClick={() => {
          console.log("Reset");
          handleReset();
        }}>Reset</button>
        <button id="plusone" onClick={() => {
          console.log("+1");
          handleAdd1("Jules");
        }}>+1</button>
        <button id="plustwo" onClick={() => {
          console.log("+2");
          handleAdd2();
        }}>+2</button>
      </div>
      <button id="clearall" onClick={() => console.log("Clear History & Results")}>Clear History & Results</button>
    </div>
  );
}

export default ControlCenter;

In this component:

  • useDispatch provides the dispatch function to trigger actions.
  • Named handler functions (handleAdd1, handleRemove2, etc.) are defined for each action, making the code more modular and reusable.
  • Each button triggers a specific action (e.g., ADD_1, REMOVE_2, RESET) when clicked, updating the count and history in the store.
  • The handleAdd1 function includes a notification parameter passed as payload: "Jules", though the reducer currently ignores this payload.
  • The "Clear History & Results" button currently only logs a message and does not dispatch an action. You could extend the reducer with a new action (e.g., CLEAR_ALL) to reset both history and count.
