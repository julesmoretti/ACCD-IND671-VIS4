Part 1: Enhanced Number Adder with Arrays, Objects, Loops, and Conditional Statements

This assignment builds on the previous number adder functionality, with a focus on incorporating more advanced JavaScript features such as arrays, objects, loops, and conditional statements. The goal is to store the history of operations, track the number of additions and subtractions, and use conditional statements to display dynamic messages.

Before You Start

  • Work from the copy you made in in-class Exercise 5 (week 3/Assignment), where every button already calls updateResults().
  • Add three empty elements to your sidebar, under the result paragraph. The steps below write into them: 
    <ul id="historyList"></ul>
<div id="summary"></div>
<p id="totalMessage"></p>
  • By the end, updateResults() looks like this. Each step below adds one line to it: 
    function updateResults() {
    document.querySelector("#resultId").innerHTML = total;
    updateHistory();   // Step 1
    updateSummary();   // Step 2
    checkTotal();      // Step 3
}

Steps to Implement:

  1. Track Operation History Using an Array

    • Description: Each time an operation (e.g., +1, -1, Reset) is performed, add that operation to the history array. The array will store all operations performed and will be displayed in the sidebar.
    • Instructions:
      • Create the array with let history = []; at the top of your script. Use let, not var: history is already a built-in browser name, and with var the browser keeps its own version, so history.push fails with “history.push is not a function”.
      • Push each operation (e.g., "-1", "Reset", "+2") into the array when a button is clicked.
      • Create a function updateHistory() with a for loop to iterate over the history array and display it as a list in the sidebar.
      • Add updateHistory(); to your updateResults() function.
      • Example:
        let history = [];
                        
// in each button listener, add: history.push("+1");  (or "-1", "Reset", etc.)

function updateHistory() {
    let historyContent = "";

    for (let i = 0; i < history.length; i++) {
        historyContent += "<li>" + history[i] + "</li>";
    }

    document.querySelector("#historyList").innerHTML = historyContent;
}

  2. Display a Summary of Operations Using an Object

    • Description: Track the total number of additions and subtractions in an operationCount object, and display this summary in the sidebar.
    • Instructions:
      • Create an object let operationCount = { additions: 0, subtractions: 0 }; at the top of your script.
      • In each button listener, increment the matching property, for example operationCount.additions = operationCount.additions + 1;
      • Display the summary in the sidebar by updating a div with the ID #summary.
      • Add updateSummary(); to your updateResults() function.
      • Example: 
        let operationCount = { additions: 0, subtractions: 0 };

function updateSummary() {
    document.querySelector("#summary").innerHTML = `Total additions: ${operationCount.additions}, <br> Total subtractions: ${operationCount.subtractions}`;
}

  3. Add Conditional Messages Based on the Total

    • Description: Display a message in the sidebar that shows whether the total is positive, negative, or zero after each operation.
    • Instructions:
      • Use an if-else statement to check the value of total.
      • Display a different message depending on whether the total is greater than 0, less than 0, or equal to 0.
      • Add checkTotal(); to your updateResults() function.
      • Example: 
        function checkTotal() {
    if (total > 0) {
        document.querySelector("#totalMessage").innerHTML = "The total is positive.";
    } else if (total < 0) {
        document.querySelector("#totalMessage").innerHTML = "The total is negative.";
    } else {
        document.querySelector("#totalMessage").innerHTML = "The total is zero.";
    }
}

  4. Implement a Clear History Button

    • Description: Add a Clear History & Results button that resets the total, clears the history, and resets the operationCount object.
    • Instructions:
      • Implement a function ClearAll() that resets the total, clears the history array, and resets the operationCount object to zero.
      • Add a button in the Control Center that calls ClearAll() when clicked.
      • Finish with updateResults(); to refresh the whole interface.
      • Example:
        function ClearAll() {
    total = 0;
    history = [];
    operationCount.additions = 0;
    operationCount.subtractions = 0;
    updateResults();
}

  5. Update the UI Based on User Actions

    • Description: Check that each button (+1, -1, Reset, etc.) changes the data, then calls updateResults() once. A finished button looks like this: 
      document
    .getElementById("addOne")
    .addEventListener("click", function() {
        total = total + 1;
        history.push("+1");
        operationCount.additions = operationCount.additions + 1;
        updateResults();
    });

Bonus Feature: Clickable History (Refactor Exercise)

In this bonus feature, you will refactor the existing code to make each item in the history list clickable. When the user clicks on a history item, it should be removed from the list using the splice() method.

Bonus Feature Instructions:

  1. Refactor the updateHistory() Function:
    • Modify the updateHistory() function so that each list item in the history has an onclick event listener.
    • This event listener should call a function removeHistoryItem(index) that removes the clicked item from the history array.
  2. Example: 
    function updateHistory() {
    let historyContent = "";
    for (let i = 0; i < history.length; i++) {
        historyContent += "<li onclick='removeHistoryItem(" + i + ")'>" + history[i] + "</li>";
    }
    
    document.querySelector("#historyList").innerHTML = historyContent;
}

function removeHistoryItem(index) {
    history.splice(index, 1); // Remove the selected item from the history array
    updateHistory(); // Update the displayed history after the removal
}
  3. Test the Functionality:
    • After implementing this feature, the user should be able to remove individual history entries by clicking on them. The displayed history list should immediately update to reflect the change.

Part 2: Your Project's Software Requirements

Separate from the Number Adder, you have been developing the UI for your own project since Week 2. Before you can test it, you need to know what it is supposed to do.

Write out the requirements for your project's interface. Each one as a user statement:

As a user, when I [do something], I expect the interface to [respond somehow], so that I can [achieve something].

For example:

As a user, when I enter a target number and press start, I expect the interface to show a live count and a stop button, so that I can monitor progress and interrupt it if something goes wrong.

Mark each requirement with a priority:

  • Must have — the interface is broken without it
  • Nice to have — improves the experience, not essential
  • Dropped — you considered it and decided against it. Say why.

Aim for 6–10 requirements. Include at least two you have dropped — deciding what not to build is a design decision, and writing down why stops you relitigating it later in the term.

Half a page is enough. This is not a document, it is a working list.

Why this matters now

Next week you will test your interface with classmates, and these requirements become the test tasks — you will hand someone the interface and ask them to do the thing your statement describes, without explaining how. Vague requirements produce untestable tasks.

This is also the exact format your HMI document uses in Week 8 for the hardware side. You are learning the notation on something small before it matters.
