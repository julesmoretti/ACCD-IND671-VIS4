This section of the class focuses on helping students understand the fundamentals of React by walking through the steps required to set up and work with a simple React project, including the introduction to JSX, props, components, and state management.

1. Setup: Creating a React App with Vite

The first step is to scaffold a new React project. We use Vite, which is what the React team now recommends — create-react-app has been deprecated and is no longer maintained.

  1. Create a New React App:

    Vite scaffolds the project for you, so there is nothing to install globally first. For this class, we’ll create a project named number-adder.

    npm create vite@latest number-adder -- --template react

    Choose the plain react template, not react-ts — we are writing JavaScript in this class, not TypeScript.

  2. Install the Dependencies:

    Vite writes the project files but leaves the packages to you:

    cd number-adder
    npm install
  3. Start the Development Server: 
    npm run dev

    This launches the app in the browser at http://localhost:5173 and sets up a live-reloading environment, so changes you make in your code will immediately reflect in the browser.

2. Anatomy of a React App

Once the React app is generated, it’s crucial to understand the basic structure of the project and what each file does. This will help students navigate the project and understand where they should write their code.

  • index.html (in the project root):

    The base HTML file that serves as the entry point for the entire application. Note that it sits at the top level of the project, not inside a public folder. It holds a single <div id="root"></div> that React renders into, plus a <script type="module" src="/src/main.jsx"> tag that loads your code.

  • /src Folder:
    • main.jsx: The entry point for the React app. It renders the root component (App.jsx) into the #root div in index.html.
    • App.jsx: The main React component. Initially, this is a functional component that returns JSX.
    • App.css: Styles for App.jsx.
    • index.css: Global styles for the app.
    • assets/: Images and icons that your components import.
  • /public Folder:

    Static files that are served as-is and copied into the build untouched, such as the favicon.

  • package.json:

    Lists project dependencies and scripts. The two you will use are npm run dev to start the development server and npm run build to produce a production build.

  • vite.config.js:

    Vite’s configuration file. You will not need to change it for this class.

Note on file extensions: any file that contains JSX must end in .jsx, not .js. Vite will refuse to build a .js file containing JSX and report that "JSX syntax is disabled".

3. JSX Format, Props, and className

React uses JSX (JavaScript XML) to define the structure of components. JSX is similar to HTML, but with some important differences. We'll cover how JSX works and how to pass data between components using props.

  • JSX Basics:

    JSX allows HTML-like syntax directly in JavaScript.

    const title = "Number Adder";
const subtitle = "React Version";

return (
  <div>
    <h1>{title}</h1>
    <h3>{subtitle}</h3>
  </div>
);
  • Props:

    Props are how you pass data from a parent component to a child component.

    function Navbar(props) {
  return <h1>{props.title}</h1>;
}

function App() {
  return <Navbar title="Number Adder" />;
}
  • className vs. class:

    Since JSX is embedded in JavaScript, class in HTML is replaced by className.

    <div className="container">Hello</div>

4. Creating a React Component and Injecting it into App.jsx

React applications are made up of components. Components are JavaScript functions (or classes) that return JSX and represent pieces of the UI. Let’s break down how to create a simple React component and integrate it into the App.jsx file.

  • Creating a Component: 
    // in a new file called Navbar.jsx
function Navbar() {
  return (
    <div id="navbar">
      <h1>Number Adder</h1>
      <h4>Item 1</h4>
      <h4>Item 2</h4>
    </div>
  );
}

export default Navbar;
  • Injecting the Component into App.jsx: 
    import Navbar from './Navbar';

function App() {
  return (
    <div>
      <Navbar />
      <p>This is the main content of the app.</p>
    </div>
  );
}

export default App;

5. State Management: useState, Props vs. State, Localized vs Distributed

State is one of the core concepts of React, allowing components to "remember" things between renders. State is different from props in that it’s local to a component and can change over time, while props are passed down from a parent component and are read-only.

  • useState Hook: 
    import React, { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Total: {count}</p>
      <button onClick={() => setCount(count + 1)}>Add 1</button>
      <button onClick={() => setCount(count - 1)}>Remove 1</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

export default Counter;
  • State vs. Props:

    Props are passed into components from parent components and are immutable. State is local to a component and can be updated.

  • Localized vs. Distributed State:

    Localized state is managed inside a single component. Distributed state refers to shared state across multiple components, often managed with context or external libraries like Redux.
